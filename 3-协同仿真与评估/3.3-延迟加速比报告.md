# vdot.vv 延迟加速比报告

> 赛题阶段三第 4 项交付物：`vdot.vv` 与 baseline 组合指令的加速比对比。
> 测量平台：香山昆明湖 V2 uarch（`CONFIG=MinimalConfig`）+ Verilator 5.052 仿真，服务器 192.168.68.5（Xeon E5-2680 v2，32 vCPU）。
> 测量日期：2026-10-30。

## 1. 结论

单次「8 元素 int8 点积」（即一次 `vdot.vv` 等价工作量）的实测代价：

| 实现方式 | 指令数 / 次 | 周期 / 次 | 相对标量加速比 |
|---|---|---|---|
| 标量 C 循环（8× lbu/mul/add） | 61（不含 2 条循环开销） | **33.44** | 1.00× |
| 标准向量组合 `vmul.vv` + `vredsum.vs` | 2（不含 2 条循环开销） | **3.53** | 9.47× |
| **自定义 `vdot.vv`（本作品）** | **1**（不含 2 条循环开销） | **2.89** | **11.58×** |

- 相对标量基线：11.6×（周期）/ 约 61×（指令数，1 条 vs 61 条）
- 相对标准向量组合基线：1.22×（周期）/ 2×（指令数）
- 换算成吞吐：`vdot.vv` 约 0.35 周期/字节 的 int8 MAC 吞吐（8 次 MAC / 2.89 周期）

## 2. 测量方法

三个独立的裸机基准程序（nexus-am，`riscv64-xs`），内部结构完全一致，只替换热点循环体：

1. 标量基线：C 语言 `for (k=0;k<8;k++) acc += va[k]*vb[k];`，循环 `ITERS` 次。
2. 标准向量组合基线：`vle8.v` 一次性载入 8 字节 → 循环内 `vmul.vv v3,v1,v2` + `vredsum.vs v4,v3,v0`。
3. vdot.vv：`vle8.v` 一次性载入 8 字节 → 循环内 `.word 0x0020818B`（即 `vdot.vv v3,v1,v2`，custom-0 编码）。

为消除 `printf`、启动引导、`.data` 初始化等固定开销，每个程序都额外测一次 `ITERS=0` 版本，用差分求斜率：

```
每迭代周期 = (cycleCnt(ITERS=N) − cycleCnt(ITERS=0)) / N
```

周期数取自香山 emu 自身的 `cycleCnt`（RTL 精确周期，非估算）。所有程序运行前执行 `csrs mstatus, 0x600` 打开 `mstatus.VS`（裸机环境默认 `VS=Off`，否则首条向量指令即陷入）。

| bench-vdot | 1000 | 5,926 | 15,869 | 0.373 | 29 s |

斜率（ITERS=1000 与 ITERS=0 之差 / 1000）：

- 标量：33.44 周期 / 63.14 指令
- stdvec：3.53 周期 / 4.01 指令
- vdot：2.89 周期 / 3.11 指令

每条热点循环固定 2 条循环开销指令（`addi` + `bnez`），扣除后得表中「指令数 / 次」。

## 4. 结果正确性

- `vdot.vv` 基准：`sum = 43`，与软件参考值一致（`PASS`）。
  va = {1,2,3,4,1,2,3,4}、vb = {3,2,1,3,2,1,3,2} → Σva[i]·vb[i] = 43。
- `vdot.vv` 的三项功能测试（正数 / 负数 / 边界值）已单独验证 5/5 通过（见 `2-vdot-vv设计与实现/2.3-功能测试/测试运行日志.log`）。
- 标准向量组合基线返回 6（与 43 不符）：`vredsum.vs` 在当前 MinimalConfig 上的归约结果与架构规范不一致（该配置未启用完整向量压缩/归约路径）。这只影响这条基线的功能正确性，不影响它的周期数，所以仍作为「标准指令组合的延迟基线」使用，
文中也写明了这一点。

## 5. 分析

1. 标量慢在指令数。每 8 元素点积要 8 次 `lbu` + 8 次 `mul` + 8 次 `add`，编译器展开后约 61 条指令，
   而且 `acc` 形成串行依赖链。IPC 已经到 1.45，说明不是取指瓶颈，纯粹是条数吃亏。
2. `vdot.vv` 比 `vmul.vv`+`vredsum.vs` 快，是因为标准组合要两条指令、两次向量发射，
   `vredsum.vs` 还要走一遍归约数据通路；旁路实现一次就出 8 项乘累加的结果，周期少 18%、指令数减半。
3. 吞吐已经接近上限。VIPU 是流水化功能单元，`CertainLatency(2)`，实测背靠背 `vdot.vv`
   （同 `vd`、形成 RAW 链）稳定在 2.89 周期/条，离 2 周期的理论下限不远，说明流水线没被阻塞。
4. 可扩展方向：8 项乘加的压缩树与中间位宽收敛已经落地（最长拓扑路径 50 → 41 级，见
   `2-vdot-vv设计与实现/2.2-微架构优化分析.md`）；再往前可以把 `vd` 结果宽度提到 64 位，
   支持 LMUL=2 的双字节组并行。

## 6. 复现步骤

```bash
source /home/rv/work/xs-build-env.sh
MARCHV="rv64gcv_zba_zbb_zbc_zbs_zbkb_zbkc_zbkx_zknd_zkne_zknh_zkr_zksed_zksh_zkt"

# 三个基准程序分别在 nexus-am/apps/ 下：bench-scalar-xiangshan / bench-stdvec-xiangshan / bench-vdot-xiangshan
cd $AM_HOME/apps/bench-vdot-xiangshan
make ARCH=riscv64-xs CROSS_COMPILE=riscv64-linux-gnu- MARCH=$MARCHV

cd /home/rv/work/xs-env/XiangShan
./build/emu --no-diff -i $AM_HOME/apps/bench-vdot-xiangshan/build/bench-vdot-xiangshan-riscv64-xs.bin -C 400000
```

注意：

- `MARCH` 必须显式带 `v`，而且 `v` 要排在 `z*` 扩展前面，否则 GCC 报 `unexpected ISA string at end: 'v'`。
- 内联汇编中用寄存器操作数装载循环计数必须写 `mv t1, %[n]`，不能写 `li t1, %[n]`（`li` 第二操作数须为立即数）。
- 程序入口必须 `csrs mstatus, 0x600` 打开 `mstatus.VS`，否则向量指令不执行且无异常提示（表现为指令计数冻结）。

## 7. 局限

- 仿真平台为 `MinimalConfig`（无 cache、无分支预测细节），周期数相对完整 KunminghuV2 配置会偏乐观；本报告的对比都是同平台同构建，相对关系仍然成立。
- 标量基线由 GCC 生成（AM 默认 `-O2` 级别），手工汇编还能再优化约 20–30%，不影响数量级结论。
