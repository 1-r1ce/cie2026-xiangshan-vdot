# vdot.vv 微架构优化分析：位宽收敛 + Wallace 压缩树

本文件记录 `vdot.vv` 数据通路从「能出结果」到「关键路径更短」的优化过程，
包括四组实现的逻辑综合对比数据、取舍理由、局限与后续路线。
配套代码：`附录/微架构综合实验/`；RTL 实体：`VIPU.scala` 的 `vdotCsa` / `vdotProds` 段。

---

## 1 问题：为什么这条指令值得优化

`vdot.vv` 落在 `FuType.vipu` 上，走 `VecPipedFuncUnit`，`VipuCfg` 的 `latency = CertainLatency(2)`。
也就是说**点积的 8 次乘加必须在 2 拍内算完**，它是 VIPU 这条流水级里最长的一条组合路径：

- `vialu` 原本只做 128 bit 内的按元素加减/逻辑，逻辑深度浅；
- `vdot` 旁路引入了 8 个 8×8 有符号乘法器 + 一个 8 操作数累加；
- 若累加写成逐级 `+&`，综合工具只会展开成 7 级串行进位链，深度与操作数个数线性相关，
  在 2 拍预算里会明显吃掉频率余量。

赛题评分表里「微架构优化分析」「设计优化独特性」两项都需要定量证据，而不是定性描述。
因此本文用开源逻辑综合（yosys）给出单元数与最长拓扑路径两项可比指标。

## 2 基线实现

原始版本（`/home/rv/work/backup/VIPU.scala.serial`，也是 `2-vdot-vv设计与实现/2.2-RTL实现.patch` 第一版的写法）：

```scala
private val vdotProdSum: SInt = (0 until 8).map { i =>
  (vs1(8 * i + 7, 8 * i).asSInt * vs2(8 * i + 7, 8 * i).asSInt).pad(32)
}.reduce((a, b) => a +& b)
private val vdotResData = Cat(0.U((dataWidth - 32).W), vdotProdSum(31, 0).asUInt)
```

问题有两个：累加写成左结合 `reduce` → 7 级串行 CPA；每级都按 32 bit 相加（连同符号扩展共 34 bit 有效宽度），
位宽远大于实际需要。

## 3 优化一：中间累加位宽收敛（34 bit → 19 bit）

单个乘积是 `sext8 × sext8`，范围 `[-16384, 16256]`，16 bit 有符号即可容纳。
8 项最坏情况：

- 最大正和：`8 × (-128) × (-128) = 131072 = 2^17`
- 最大负和：`8 × 127 × (-128) = -130048`

因此 **19 bit 有符号数（`[-262144, 262143]`）足以精确表示任意 8 项点积**，且留 1 bit 余量。
32 bit 的写回位宽只在最后一步做符号扩展，不参与中间累加 → 中间位宽可以从 34 bit 收窄到 19 bit，
等价于每级加法器砍掉 15 bit 的进位链。

写回仍是 32 bit 输出（方案 C）：

```scala
private val vdotResData = Cat(0.U((dataWidth - 32).W), vdotSum19.pad(32).asUInt)
```

> 位宽的模运算性质保证收窄不改变结果：8 项和真实值落在 19 bit 可表示范围内，
> 截到 19 bit 后再符号扩展回 32 bit，与直接在 32 bit 里算是逐位相同的。

## 4 优化二：8 操作数 Wallace 压缩树（3:2 CSA）

用 3:2 进位保留加法器把 8 个操作数压到 2 个，再只做 1 级进位传递加法：

```scala
private def vdotCsa(a: UInt, b: UInt, c: UInt): (UInt, UInt) =
  (a ^ b ^ c, Cat(((a & b) | (a & c) | (b & c))(17, 0), 0.U(1.W)))

private val (w0s, w0c) = vdotCsa(vdotProds(0), vdotProds(1), vdotProds(2))
private val (w1s, w1c) = vdotCsa(w0s, w0c, vdotProds(3))
private val (w2s, w2c) = vdotCsa(vdotProds(4), vdotProds(5), vdotProds(6))
private val (w3s, w3c) = vdotCsa(w2s, w2c, vdotProds(7))
private val (w4s, w4c) = vdotCsa(w1s, w1c, w3s)
private val (w5s, w5c) = vdotCsa(w4s, w4c, w3c)
private val vdotSum19 = (w5s + w5c)(18, 0).asSInt
```

结构上是 4 级 CSA：8 个乘积先压到 6 个、再到 4 个和 3 个，最后剩 2 个操作数做 1 次 CPA，关键路径与操作数个数解耦。
CSA 只用异或/与/或门，没有进位链，天然适合压在乘法器之后。

> 实现细节坑：Chisel 里 `w5s + w5c` 的结果位宽是 `max(19,19)+1 = 20` bit，
> 直接 `.asSInt` 会按 bit19 扩展符号（该位恒为 0，负数会被当成正数）→ 必须先取 `(18, 0)` 再 `asSInt`。

## 5 量化评估（yosys 0.33，ABC 面积导向综合）

方法：把四种数据通路写成等价的 Verilog 模块（端口统一 `input [127:0] vs1, vs2; output [31:0] dot`），
用 `yosys -p "read_verilog <m>.v; synth -top <m>; stat; ltp -noff"` 综合到通用门级，
取 单元数（cells） 与 **最长拓扑路径级数（Longest topological path）** 两个指标。
门级映射与工艺无关，但级数是频率的合理代理：级数越少，同一工艺下可综合的频率越高。

| 变体 | 累加位宽 | 累加结构 | 单元数 | 最长拓扑路径 | 相对原实现 |
| --- | --- | --- | --- | --- | --- |
| `vdot_serial`（原实现） | 34 | 7 级串行 CPA | 4073 | 50 | 基线 |
| `vdot_tree` | 34 | Wallace 4 级 CSA + CPA | 4262 | 51 | +4.6% 面积 / +2% 路径 |
| `vdot_serial19` | 19 | 7 级串行 CPA | 4022 | 42 | −1.3% 面积 / **−16% 路径** |
| `vdot_tree19`（**采用**） | 19 | Wallace 4 级 CSA + CPA | 4215 | 41 | +3.5% 面积 / **−18% 路径** |

结论与解读：

1. 深度收益主要来自位宽收敛。34 → 19 bit 让串行版从 50 级降到 42 级（−16%），这一步几乎不花面积
   （4073 → 4022，反而略小，因为少了 15 bit 的进位链与符号扩展）。
2. 压缩树的收益在这套综合流程下只有 1 级（42 → 41）。原因是 `synth` 默认调 ABC 做面积导向重综合，
   手写的 CSA 结构会被重新打平再优化，结构优势被部分抹平。换句话说，在这个口径下位宽比拓扑
   更能决定深度。
3. 乘法器才是剩余路径的主体。19 bit 压缩树版仍有 41 级，其中约 30 级来自 8×8 乘法器的
   Booth/阵列映射。想再往下压必须动乘法器本身，见 §8。
4. 采用 `vdot_tree19` 的理由：它是四个变体里路径最短的一个，且压缩树让累加部分与操作数个数无关，
   为将来扩展到 16 元素（SEW=8, LMUL=2）留了结构（8 → 16 操作数时串行版会再涨 1 级，树只涨 1 级 CSA）。
   代价是比 `serial19` 多 193 cells（+4.8%）；若面积紧张，`serial19` 是可随时替换的备选
   （换回只需把 `vdotCsa` 链删掉、改成 `reduce(_ +& _)`）。

## 6 功能等价性

优化只改中间位宽与加法拓扑，不改语义：

- 位宽收敛：由 §3 的范围证明，19 bit 可精确表示任意 8 项点积，模运算下与 32 bit 结果一致；
- 压缩树：CSA 是恒等式 `a + b + c = (a^b^c) + 2·((a&b)|(a&c)|(b&c))`，逐级等价变形。

优化落地后（2026-10-30 05:50 UTC 重建的 `build/emu`）重新跑了完整回归：

| 项目 | 结果 |
| --- | --- |
| 5 个功能用例（正数 2040 / 负数 4 / 最大同号 129032 / 最小同号 131072 / 极端混合 −130048） | 全部通过，与优化前逐位一致，见 `2-vdot-vv设计与实现/2.3-功能测试/测试运行日志.log` |
| 运行指标 | instrCnt 21,500 / cycleCnt **74,585** / IPC 0.288262 |
| RTL × NEMU 协同仿真 | 打开 difftest 后全程零不一致，见 `3-协同仿真与评估/日志/协同仿真日志.log` |

`cycleCnt` 与优化前完全一样（74,585），这是预期的：本次优化只压组合逻辑深度，
既没改 `VipuCfg.latency = CertainLatency(2)` 也没改指令数，周期数自然不会动。
收益体现在「同样 2 拍预算下更容易满足时序」，要和 §5 的综合数据一起看。

## 7 局限

1. yosys 的 `ltp` 是拓扑级数，不是带工艺库的 STA 结果（没有单元延迟、扇出、布线负载），
   只能用于同类实现之间横向比较，不能直接换算成 MHz。
2. 综合是面积导向（`synth` 默认脚本），不是时序导向；若改用 `abc -script +delay` 或开 `dfflibmap`
   到具体工艺库，绝对数字会变（结构优势通常会更明显一些，但我们的结论建立在同一口径下的相对比较上）。
3. 未评估功耗；压缩树的翻转活动通常低于串行进位链，但未量化。
4. 实测加速比（`3-协同仿真与评估/3.3-延迟加速比报告.md`）是周期数层面的，
   与本文的关键路径层面是两个正交维度：前者由指令数与 uop 数决定，后者由组合深度决定。

## 8 后续优化路线

| 方向 | 预期收益 | 代价/风险 |
| --- | --- | --- |
| 复用 `VimacU` 已有乘法器阵列，而不是新增 8 个 8×8 | 面积显著下降（乘法器占 30/41 级也占大头面积） | 需要跨 FU 调度，改动面大 |
| Booth 编码 + 4:2 压缩器替代现成 `*` | 乘法器深度从 ~30 级降到 ~20 级 | Verilog/Chisel 手写乘法器，验证成本高 |
| 累加流水化（latency 2 → 3） | 组合路径减半 | 改 `VipuCfg.latency`，影响 scoreboard 与唤醒时序 |
| 支持 SEW=16 / LMUL=2（16 元素） | 一条指令覆盖更长的点积 | 需要 32 bit 中间和与另一次压缩树 |

## 9 复现

```bash
# 服务器上（Ubuntu 24.04）
sudo apt-get install -y yosys            # Yosys 0.33
cd /home/rv/work/yosys-exp
for m in vdot_serial vdot_tree vdot_serial19 vdot_tree19; do
  echo "=== $m ==="
  yosys -p "read_verilog $m.v; synth -top $m; stat; ltp -noff" 2>/dev/null \
    | sed -n '/Printing statistics/,$p' | grep -E "Number of cells|Longest topological"
done
```

四个变体的 Verilog 与一键脚本见 `附录/微架构综合实验/`。
