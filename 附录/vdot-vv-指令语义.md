# vdot.vv 指令语义拆解

> 本文是我们对官方语义的理解与推演，不是官方文本。官方原文见赛题页面
> <https://rv.cie.org.cn/direction?id=8>，官方语义图见本目录的
> [官方语义图.jpg](官方语义图.jpg)。

## 官方语义

```python
def vdot_vv(vs1, vs2, sew=8):
    # 根据SEW设定，从两个源向量寄存器中各取8个int8数据
    result = 0
    for i in range(8):
        result += sign_extend(vs1[i]) * sign_extend(vs2[i])
    # 结果写入目标向量寄存器vd的第一个元素
    vd[0] = result
    vd[1..VLEN-1] = 0   # 其他通道清零
```

## 逐条拆解

### 1. 数据来源：8 个 int8

- SEW = 8 → 每个 element 是 1 字节，有符号（`sign_extend`）。不是 u8。
- 一次取 8 个 element，即 8 字节 = 64 bit。VLEN = 128 时刚好是半个向量寄存器。
- 两个源向量寄存器 `vs1`、`vs2` 各取低 8 个 element（element 0–7）。

> 待确认：香山昆明湖 V2 的 vector unit 里，`vs1[i]` 的 i 是"寄存器内第 i 个字节"还是"第 i 个 lane
> 的元素 0"。VLEN=128、SEW=8 时每个 lane 有 16 个字节，两者排布不同。**这一点必须从 RTL 的
> element 排布确认后再落笔**，写错会连带设计文档和测试向量一起错。

### 2. 乘积位宽

`sign_extend(int8) × sign_extend(int8)` → 最宽需要 16 bit（`-128 × -128 = 16384` 需要 15 bit + 符号）。
所以单次乘积用 int16 表示是无损的。

### 3. 累加位宽

8 项 int16 相加：最坏情况 `8 × 16384 = 131072`，需要 18 bit 有符号（范围 ±131071）。
即：

- 中间累加器至少 19 bit（含符号）才无损，工程上取 32 bit 最省心。
- 若取 16 bit 累加会溢出，**必须在设计文档里显式说明溢出处理策略**（饱和 / 回绕 / 扩位）。

### 4. 写回宽度（最大的歧义点）

`vd[0] = result` —— `vd[0]` 在 SEW=8 时只有 8 bit。而 `result` 是 18+ bit。

官方语义没有说明截断规则。三种自洽的选择：

| 方案 | 行为 | 优点 | 风险 |
| --- | --- | --- | --- |
| A. 低 8 位截断 | `vd[0] = result[7:0]` | 最贴近"element 是 8 bit"的字面语义 | 大量真实数据溢出，功能上很弱 |
| B. 饱和到 int8 | `clamp(result, -128, 127)` | 数值单调，AI 场景更可用 | 与字面语义不符 |
| C. 扩位写回 | 写 `vd[0..3]` 共 32 bit（int32 结果） | 信息无损，最贴合点积实际用途 | 违背"其他通道清零"的表述 |

建议：默认按 A（低 8 位截断）实现保证与官方语义一致，并在设计文档里把 B/C 作为
扩展应用潜力要讨论的话，定稿前建议在赛题咨询群里问一次。

### 5. 其余通道清零

`vd[1..VLEN-1] = 0` —— 这是整寄存器清零，不是只清 element。

- 实现上最简单：目标寄存器的旧值不进数据通路，直接用写使能 + 清零掩码覆盖整个 vd。
- 好处：不产生对 vd 旧值的 RAW 依赖 → **免去读 vd 的端口和一次排序开销**，可以顺带写进
  "设计优化独特性"（微架构优化）里。
- 注意：清零的粒度和香山 vector unit 的写回通路（按 lane / 按 chunk 写回）要对齐，
  否则会与相邻指令的写回冲突。

## 待定决策清单

- [ ] `vs1[i]` 的 element 到 lane/byte 的映射（查 RTL / 用 `vadd.vv` 波形反推）
- [ ] 编码：custom opcode 分配（RVV 预留的 `custom-0..3` 还是香山自有的扩展区）
- [ ] 写回截断策略（A / B / C）
- [ ] 累加器位宽（19 / 32 bit）
- [ ] 是否支持 `vm` 掩码位（官方语义未涉及 → 建议 `vm = 1'b1` 固定不掩码，非法组合的行为写进文档）
- [ ] 是否支持 `vd` 与 `vs1/vs2` 重叠（overlap）——若清零策略使 vd 不被读，则天然支持重叠
- [ ] 是否需要处理 `vl`（向量长度寄存器）的影响——语义里固定取 8 个，应明确"忽略 vl"还是"要求 vl≥8"
