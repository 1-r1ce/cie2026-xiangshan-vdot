## 三、部署步骤

### 1. 系统与镜像源

安装 Ubuntu 24.04 Server，镜像源设为 `https://mirrors.tuna.tsinghua.edu.cn/ubuntu`，安装时勾选 OpenSSH Server。

### 2. 工具链

```bash
# 系统依赖
sudo apt update
sudo apt install -y build-essential git ccache help2man perl python3 zlib1g-dev \
    libgoogle-perftools-dev numactl libsqlite3-dev libzstd-dev \
    gcc-riscv64-linux-gnu g++-riscv64-linux-gnu open-vm-tools

# LLVM 19 → /usr/local/llvm
# GraalVM JDK 21 → /opt/graalvm-jdk-21
# mill 0.12.3 → /usr/local/bin/mill
# Verilator 5.052：源码编译（autoconf flex bison）
```

### 3. 环境变量（关键）

香山构建在非交互 shell 下不会自动加载 `~/.bashrc`，且 `env.sh` 只设 `XS_PROJECT_ROOT` / `NEMU_HOME` / `AM_HOME` / `NOOP_HOME` / `DRAMSIM3_HOME`，**不含 java 与 clang 的 PATH**。为此单独固化一个脚本：

```bash
# /home/rv/work/xs-build-env.sh
export JAVA_HOME=/opt/graalvm-jdk-21
export PATH=/usr/local/llvm/bin:/opt/graalvm-jdk-21/bin:$PATH
export XS_PROJECT_ROOT=/home/rv/work/xs-env
export NEMU_HOME=$XS_PROJECT_ROOT/NEMU
export AM_HOME=$XS_PROJECT_ROOT/nexus-am
export NOOP_HOME=$XS_PROJECT_ROOT/XiangShan
export DRAMSIM3_HOME=$XS_PROJECT_ROOT/DRAMsim3
```

**每个构建脚本开头都要 `source /home/rv/work/xs-build-env.sh`**，否则会遇到以下两个错误：

| 现象 | 原因 |
|---|---|
| `mill ...: exec: java: not found` | GraalVM 不在 PATH |
| `ccache: error: Could not find compiler "clang++" in PATH` | LLVM 不在 PATH，Verilator 生成的 Makefile 默认用 `clang++` |

### 4. NEMU（参考模型）

```bash
cd $NEMU_HOME
make riscv64-xs-ref_defconfig
make -j20
# 产物：build/riscv64-nemu-interpreter-so（约 1.5 MB，供 difftest 做参考模型）
```

> 注意：`riscv64-xs-ref` 只产出 `.so` 参考模型，**不产出独立的 `riscv64-nemu-interpreter` 可执行文件**，这是正常的。

### 5. XiangShan 仿真器

```bash
source /home/rv/work/xs-build-env.sh
cd $NOOP_HOME

# 首次（或换 CONFIG）必须先清理，否则 make 会复用上一轮产物
rm -rf build/rtl build/generated-src build/emu-compile build/emu

make emu -j16 CONFIG=MinimalConfig JVM_XMX=24G
# 产物：build/emu（约 68 MB）
```

构建耗时（32 vCPU）：

| 阶段 | 耗时 |
|---|---|
| Chisel 展开（mill） | 约 12 分钟 |
| firtool 转 SystemVerilog + seq-mem 替换 | 约 5 分钟（产物 997 MB） |
| Verilator `--cc` 代码生成 | 约 5 分钟 |
| clang++ 编译 500+ 编译单元 | 约 3–10 分钟（有 ccache 缓存时更快） |

## 五、已知约束

1. **换 `CONFIG` 必须清理 `build/`**，否则静默复用旧 RTL（详见 `docs/tech/仿真速度问题排查报告.md`）；
2. **`-F`（flash 启动）路径会让核卡在 bootrom 拷贝循环**，阶段一/二直接用 `-i <image>` 从 DRAM 启动；
3. 仿真速度约 570 周期/秒（MinimalConfig），单次 hello 30–50 秒 —— 详见排查报告。
