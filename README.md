# 2026 CIE 全国 RISC-V 大赛：香山昆明湖 V2 上的 vdot 向量点积指令

参赛队伍 panpan最努力 · 齐鲁师范学院 · 指导教师 冯希叶
赛题：面向边缘 AI 大语言模型推理的 RISC-V 自定义 vdot 指令设计（基于「香山」昆明湖 V2 处理器）

## 作品概述

大语言模型推理里最吃算力的算子之一是矩阵乘，拆开就是大量的**整数点积**：两段 8 位数据逐对相乘再累加。
通用处理器上没有对应指令时，这类计算只能靠标量循环（每次 8 对乘法加法，约 60 条指令）或标准向量指令组合
（`vmul.vv` 后再 `vredsum.vs` 归约）来实现。

本作品给香山昆明湖 V2 加了一条自定义向量指令 `vdot.vv vd, vs1, vs2`：从两个源向量寄存器各取 8 个 int8，
做 8 对乘累加，结果一次写回 `vd[0]` 的低 32 位。RTL 侧沿香山已有的向量功能单元（VIPU）旁路实现，不新造发射通路；
NEMU 参考模型同步扩展，两侧在 difftest 下逐条指令一致。

实测（昆明湖 V2 `MinimalConfig` + Verilator 5.052，周期数取自 RTL）：

| 实现方式 | 指令数 / 次 | 周期 / 次 | 相对标量 |
|---|---|---|---|
| 标量 C 循环（8× lbu/mul/add） | 61 | 33.44 | 1.00× |
| `vmul.vv` + `vredsum.vs` 标准组合 | 2 | 3.53 | 9.47× |
| **自定义 `vdot.vv`** | **1** | **2.89** | **11.58×** |

相对标准向量组合，周期少 18%、指令数减半；背靠背发射稳定在 2.89 周期/条，离 VIPU 的 2 周期理论下限不远。

在此基础上还做了一轮数据通路优化：把 8 项乘积的累加从 32 bit 串行链收敛成 19 bit + Wallace 压缩树，
yosys 综合下最长拓扑路径从 50 级降到 41 级（−18%），面积只增加 3.5%。

## 环境与复现

开发与测量平台：Ubuntu 24.04（VMware ESXi 虚拟机，32 vCPU Xeon E5-2680 v2 / 31 GiB），
香山仓库 `OpenXiangShan/XiangShan` 昆明湖 V2 分支，Verilator 5.052，LLVM 19.1.7，
GraalVM JDK 21，`riscv64-linux-gnu-gcc` 13.3.0，NEMU（`riscv64-xs-ref` defconfig）。

复现主要步骤：

```bash
# 1. 环境与工具链（详见 1.1 文档）
source /home/rv/work/xs-build-env.sh

# 2. 应用 RTL 补丁（详见 2.1、2.2 文档）
cd XiangShan && git apply /path/to/2-vdot-vv设计与实现/2.2-RTL实现.patch

# 3. 重建仿真器（约 20 分钟）
rm -rf build/rtl build/generated-src build/emu-compile build/emu
make emu -j16 CONFIG=MinimalConfig JVM_XMX=24G

# 4. 编译并运行功能测试
cd $AM_HOME/apps/vdot-xiangshan && make clean && make ARCH=riscv64-xs CROSS_COMPILE=riscv64-linux-gnu-
cd /home/rv/work/xs-env/XiangShan && ./build/emu -b 0 -e 0 --no-diff \
  -i $AM_HOME/apps/vdot-xiangshan/build/vdot-xiangshan-riscv64-xs.bin -C 200000
```

阶段三的协同仿真要在 NEMU 侧应用 [`3.1-NEMU扩展.patch`](3-协同仿真与评估/3.1-NEMU扩展.patch)，
把新编出的 `riscv64-nemu-interpreter-so` 放到香山的 `ready-to-run/` 下，再把 emu 的 `--diff` 指向它，
具体命令在 [`3.1-NEMU扩展与协同仿真.md`](3-协同仿真与评估/3.1-NEMU扩展与协同仿真.md) 里。

复现时有三个容易踩的坑，文档里都写了原因：参考模型与 RTL 的 flash 启动预设必须一致（否则第 2 条指令就报
`t0 different`）；裸机程序要先 `csrs mstatus, 0x600` 打开 `mstatus.VS`，否则向量指令静默不执行；编译测试程序要显式给
`MARCH` 且 `v` 必须排在 `z*` 扩展前面。

## 数据口径

- 指令数与周期数来自 emu 的 `instrCnt` / `cycleCnt`，逐次运行完全一致；墙上时间随机器负载在 30 秒到 6 分钟之间浮动，
  各文档里记的是区间而不是固定值。
- 所有对比都在同一份 `MinimalConfig` 构建、同一台机器上完成，因此横向倍数关系可比；换成完整昆明湖 V2 配置
  会因 cache 与分支预测细节不同而变化，但不影响相对结论。
- 标准向量组合基线返回的归约值（6）与架构规范不符，是该 `MinimalConfig` 既有的局限，这条基线只用于计时，
  报告里已注明。
